Developer tools

Destructive ops for resetting test accounts. Each action is permanent.
DEV ONLY. These actions wipe database rows. The auth.users row and every cascading FK (enrollments, lesson_progress, study_sessions, quiz_attempts, assignments, activity_log, parental_consents, per-block comments) go with it. Catalogue content (lessons, units, topics) stays in place but authored-by / published-by / audit-log actor pointers are set to null. There is no undo. The audit log records every action.

Look up + delete a user

Search by email. The user must exist in auth.users; a half-signed-up account without a profile row will still appear, but the deletion will skip the profile step.

Look up + delete anything by UUID

Paste any UUID and we'll tell you which table(s) it lives in (lessons, blocks, comments, topics, units, subjects, profiles, invites, assignments, classes, schools, lesson_progress, quiz_attempts, study_sessions, auth.users). For auth.users we'll point you at the "delete a user" tool above — the rich cascade logic lives there.
